# 演化機制：讓脈絡群島自己長大

這份文件說明這門課怎麼「自己長大、自己進化」：問題從哪裡進來、誰把它變成修改、什麼關卡擋住壞修改、學員怎麼看到它變了。

## 為什麼要有這個

這門課教的是 AI 工具。工具每幾個月就變一次，所以課程內容一定會過時；學員卡住的地方，寫課的人通常也看不到。
如果只能靠作者想到才改，課程會慢慢變成一份過時的講義。
所以這套機制要做到三件事：**問題會自己浮出來、修改會自己被起草、壞修改會自己被擋下**。最後一步「發布」仍然由人決定。

## 一圈怎麼轉

```
 學員／貢獻者 ──回報這題、投稿案例──▶ GitHub issue（有固定表單）
       ▲                                     │
       │                                     ▼
 線上看到「有更新」           每週自動體檢（GitHub Actions）
 讀「更新紀錄」               ─ 內容合約、四語對齊、哪座島該重新驗證
       ▲                      ─ 有事才更新一張「演化看板」issue
       │                                     │
 維護者核可 → 併入 main → GitHub Pages 自動上線   ▼
       ▲                      本機演化引擎 tools/evolve.py
       │                      ─ 收集：issue＋過期島嶼＋體檢失敗
       └──── 報表＋一行採用指令 ◀─ 起草：每件事開一個分支，由 AI 改繁中＋英日
                              ─ 驗收：跑 tools/check.py，不過就丟掉
```

## 四個部分

### 1. 養分入口：問題怎麼進來

- **頁面上的「回報這題」**：每座島、每個回合的底部都有。按下去會開一個 GitHub 新 issue 頁面，**只預填島號、回合、語言、內容版本**，不會帶學員寫的答案。學員自己看過、自己按送出才算數，所以「進度不會上傳」這個承諾不變。
- **issue 表單**（`.github/ISSUE_TEMPLATE/`）：過時了、看不懂／卡住、答案有錯、投稿新 Boss 案例、翻譯問題。表單欄位就是改內容需要的資料（例如投稿案例要附「為什麼」）。
- **新鮮度**：`data.js` 的 `window.FRESHNESS` 記每座島上次被人驗證的日期，以及哪些說法依賴當下的工具（`watch`）。有 `watch` 的島 3 個月沒驗證、其他島 12 個月沒驗證，就算「該重新驗證」。

### 2. 骨架：讓內容長得進去

- **內容合約**（`tools/check.py`）：每座島必填的欄位、抽問 4 題各 4 個選項、答案編號在範圍內、每題抽問和 Boss 都要有「為什麼」。README 的原則「每個新題目都要能說出為什麼」由程式擋，不靠記得。
- **四語對齊**：英日版跟繁中版的島嶼、題數、選項數、正確答案位置都要一樣。繁中改了某一句、英日沒跟著改，會被 `tools/i18n.lock.json` 抓出來，列出是哪一句。翻好之後執行 `python3 tools/check.py --accept-i18n` 才算同步。
- **產生檔要最新**：簡體版、英日版的 `index.html` 都是產生出來的。體檢會重新產生一次，跟倉庫裡的比，不一樣就報錯。一行全部重建：`python3 tools/build_all.py`。
- **島的數量不寫死**：徽章總數、王冠島的標題都從資料算。要加第 13 座島，只改 `data.js`（和英日版）。

### 3. 守門：壞修改怎麼被擋下

- 每次推送和 PR 都跑 `tools/check.py`（`.github/workflows/check.yml`）。沒過，GitHub 會標紅。
- 演化引擎起草的修改，一律先過 `check.py` 才留下；沒過的分支直接刪掉，並記在本機帳本，不會重複嘗試同一件事。
- **AI 不會自己發布**：引擎只在本機開分支，不推送、不開 PR、不關 issue。併入 main（等於上線）由維護者決定。

### 4. 記憶：學員怎麼看到它變了

- `window.CONTENT_VERSION`：內容版本（日期）。每次內容有改就更新。
- 每座島的 `FRESHNESS[id].changed`：這座島最後一次內容修改的日期。學員上次來之後有改過的島，航海圖上會出現「有更新」，點進去之後消失（只存在學員自己的瀏覽器）。
- `更新紀錄.md`：每次內容變動寫一行，寫改了什麼、為什麼改（引用 issue 編號）。

## 演化引擎怎麼用（維護者）

```bash
python3 tools/evolve.py              # 只收集：列出待處理的事，產生報表 .evolve/report.html
python3 tools/evolve.py --draft 2    # 另外挑 2 件交給 AI 起草，每件一個分支，驗收過才留
```

- 需要：`gh`（讀公開 issue）、`claude`（起草）、`node`（讀 data.js）、有 opencc 的 Python（重建簡體版）。
- 帳本與報表在 `.evolve/`，不進版控。
- 報表裡每個留下的分支都附三行指令：看差異、採用（併入 main）、丟棄。

## 刻意不做的事

- 不收集學員資料、不放分析碼。要知道學員卡在哪，只靠學員自己按「回報這題」。
- AI 不准自動上線。課程內容公開，錯一題就是對外教錯。
- 不收只教招式的模板：起草的提示詞要求每個新增或修改都附「為什麼有效、何時失效」，合約也會檢查。
