# コンテキスト群島：プロンプト＆コンテキストエンジニアリング、ゼロから身につくまで

[繁體中文](README.md) ・ [English](README.en.md)

技術の予備知識がない社会人のための、12 週間の自習／研修用コースです。インストール不要、ブラウザで開くだけで遊べる Web ページになっています。

**オンラインで遊ぶ：<https://shanheguanjia-l.github.io/context-islands/ja/>**（[繁體中文](https://shanheguanjia-l.github.io/context-islands/)・[简体中文](https://shanheguanjia-l.github.io/context-islands/zh-hans/)・[English](https://shanheguanjia-l.github.io/context-islands/en/) もあります。右上からいつでも切り替えられ、進捗は全言語で共通です）

3 つの方法を組み合わせ、それぞれがひとつの役割を担います：

- **オクタリシス（八角フレームワーク、Yu-kai Chou 氏が提唱したゲーミフィケーションの枠組み）** は「学びたいか」を担当：12 の島、失敗モンスター、バッジ、ブラックスワン・イベント、復習しないと風化する知識の城。
- **ポモドーロ・テクニック** は「集中できるか」を担当：1 島＝6 ラウンド＝25 分のポモドーロ 6 個。
- **ファインマン・テクニック** は「本当にわかったか」を担当：どの島でも、12 歳の子にわかる言葉で原理を説明します。

島をクリアする条件はポイントではなく、「身についたレベル 3」——変更する前に結果を予測し、その理由を言えること——に到達することです。

## 使い方

1. 上のオンライン版を開くか、フォルダをダウンロードして `ja/index.html` をブラウザで開きます（オフラインでも動きます）。
2. ふだん使っている AI チャットツールを隣に開き、各島の「実験室」ラウンドのプロンプトを実行します。
3. 進捗は自分のブラウザ（localStorage）にだけ保存され、どこにも送信されません。パソコンを替える前に「記録」ページから書き出してください。ページの「この問題を報告」は GitHub の報告ページを開いて島とラウンドを入れるだけで、あなたが書いた内容は含まれず、「送信」を押すまで何も送られません。

講師の方は、海図の「フリーモード」にチェックを入れると全島を解放できます。

## 第 0 週：幹（まずここから）

テクニックを学ぶ前に、幹の 5 ラウンドを通ります：

1. **T1 スコアボード**：答えを知っている 10 のことを AI に聞き、「正解・不正解・流暢だが誤り」の 3 つだけを記録する。プロンプトは変えない。
2. **T2 机を壊す**：わざと 3 回壊す（同じ質問を新しい会話で 5 回、事実を書く／書かない、長文の真ん中にルールを埋める）。毎回まず予測を書く。
3. **T3 ひとこと**：「モデルには机の上の紙しか見えない」を 12 歳にもわかる言葉で説明し、さっき自分で見た結果と照らし合わせる。
4. **T4 4 つの層**：そのひとこと、このターンの机の上のすべて、毎ターン誰が机を並べ直すか、「完了」の定義——各層がいつ壊れたと言えるか、どう確かめるか。
5. **T5 卒業**：教わっていない失敗例 2 つについて、壊れた層と根拠を示す。2 問とも正解で合格。

幹を通ると第 1–12 島がすべて開き、**壊れたら引くツールカード**になります（海図のカードに症状を表示）。順番どおり第 1 島から始めることもできます。島 2・6・8・9・10・11 には「2026 年 11 月の補足」を追加しました。

## ファイル構成

- `index.html`、`data.js`：繁体字中国語の原本（正本）。
- `ja/data.js`：日本語の教材内容（人手で翻訳）。**`data.js` を変更したら、こちらも更新してください。**
- `ja/index.html`：`tools/build_ja.py` が原本の `index.html` から対訳表で生成します。直接編集しないでください。
- `en/`、`zh-hans/`：英語版・簡体字中国語版（同様にスクリプトで生成）。
- `課程設計.md`：コース設計の全文（繁体字中国語）。
- `meta.js`：進化の記録（コンテンツ版、各島を最後に検証・変更した日）。全言語で共用。
- `更新紀錄.md`：更新履歴。内容の変更ごとに 1 行。
- `tools/build_all.py`：生成ファイルをすべて作り直してチェック。`tools/check.py`：チェック。`tools/evolve.py`：進化エンジン。

## コントリビュート

ボス事例の追加、他言語への翻訳、モデルの更新で古くなった実験の修正などを歓迎します。ルールはひとつだけ：新しい項目はどれも「なぜ効くのか、いつ効かなくなるのか」を説明できること。小手先のテンプレートだけを教えるものは受け付けません。

実験には必ず架空のデータか、個人を特定できないよう加工したデータを使ってください。

いちばん簡単なのは、コースのどのラウンドでも「この問題を報告」を押すか、issue の「ボス事例を投稿」フォームを使うことです。ファイルを直接編集する場合は `python3 tools/build_all.py` を実行し、「錯誤 0 項」（エラー 0 件）になってから PR を送ってください。push するたびに同じチェックが自動で走ります。

## このコースの育ち方

AI ツールは変わり続けるので、コースは必ず古くなります。そこで自分で育つ仕組みを入れています。学習者の報告と毎週の自動チェックで直すべき点が浮かび上がり、メンテナーが手元の進化エンジンで AI に下書きさせ、チェックに通らない修正は捨て、最後に人が確認してから公開します。海図には「更新あり」が表示されます。詳しくは [docs/演化機制.md](docs/演化機制.md)（中国語）。
